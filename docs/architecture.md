# Архитектурные решения

## Референсы

Все четыре репозитория изучены по локальным копиям с проверенными Git remotes. Публичная веб-страница Dota Spins открылась. Для трёх репозиториев dev-parallaxsoft веб-проверка не вернула исходники, поэтому структура и конфигурации изучены локально.

| Проект                                                     | Заимствованный подход                                                                                                                              |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Dota Spins](https://github.com/tereshchenkoID/dota-2)     | Регистры, взвешенный пул символов, независимый расчёт линий и эффектов, раздельное представление анимации, JavaScript и локализованный App Router. |
| [betman](https://github.com/dev-parallaxsoft/betman)       | PascalCase для визуальных модулей, SCSS Modules и Sass API для повторно используемых правил.                                                       |
| [affiliate](https://github.com/dev-parallaxsoft/affiliate) | Группировка импортов, локализованная маршрутизация и разделение интерактивной оболочки и функциональных модулей.                                   |
| [daily-hub](https://github.com/dev-parallaxsoft/daily-hub) | Prettier с одинарными кавычками, без точек с запятой и с завершающими запятыми ES5.                                                                |

Исходники, дизайн и игровые ассеты референсов в проект не перенесены. JavaScript использует правила ESLint и группы импортов Betman, а SCSS — его порядок свойств. Классы оформленных элементов задаются явно в JSX и принадлежат локальному SCSS-модулю.

## Данные, движок и интерфейс

- Кампании задают точки карты, герои — индивидуальные маршруты и параметры. Граф строится из этих конфигураций. В общей схеме узлов описаны переходы, условия и награды. Локали используют идентификаторы контента, поэтому язык можно менять во время сохранённого испытания.
- Команда сессии включает ожидаемые ID героя и узла. Команда боя включает номер хода. Проверка контекста ограничивает устаревшие действия из вкладок или переходов назад.
- Zustand держит последний зафиксированный снимок для интерфейса. Адаптер применяет команду внутри транзакции IndexedDB. Подписка BroadcastChannel уведомляет другие вкладки о смене версии снимка.
- Контракт адаптера состоит из `load()`, `update(reducer)` и `replace(save)`. Модель данных сериализуется в JSON и проходит валидацию на границе хранилища. Обработка конфликта и идемпотентность наград остаются в слое сохранений и сессии.
- Прогресс боя, урон, фазы и флаг кинематографичной сцены записываются атомарно. Контроллер интерфейса закрывает сцену отдельной командой. Перезагрузка может снова показать сцену, пока флаг активен, с уже рассчитанным уроном.
- Next.js предварительно рендерит локали и игровые маршруты в `.next/`. Сборка запускается через `next start` или пресет Next.js на Vercel. Граф и сцены загружаются в игровой части. WebP и шрифты обслуживаются с того же источника. Серверное хранилище и платные сервисы не нужны.

## Фазы реализации

Фундамент и локализация → публичная главная → кампании и реестр героев → карта и сюжетный граф → движки мини-игр → бой, награды и прогресс → иллюстрации и кинематографичные сцены → интеграционные тесты и проверка production-сборки.
